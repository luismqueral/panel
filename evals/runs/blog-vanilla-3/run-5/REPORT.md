## 2. Unclear, contradictory, or missing instructions

1. **`build.md` step 5 vs `recipes/contracts.md` error codes:** step 5 says a save that throws `forbidden` shows "You were signed out…". The contract says `forbidden` means "This account isn't allowed". The first message is wrong for that case.
2. **`build.md` step 4 vs `recipes/client/auth.js`:** the contract wants the "isn't allowed" message when a load throws `forbidden`. But `auth.js` only sets it when `session()` itself is refused. The panel has to pass the message in itself, and no step says so.
3. **`build.md` step 5, "Show word count":** it writes into the body's `help` slot. Nothing says what happens if the field also has its own `help` text.
4. **`build.md` step 4, "What is mounted":** it doesn't say when the save bar mounts (during loading, or only when ready), or how long the create dialog lives. It only says the confirm dialog stays mounted.
5. **`build.md` step 4 Routing and Status:** it doesn't say whether publish checks run before or after the confirm dialog. Both orders fit P3 and P4.
6. **`build.md` step 4 tables:**
   - The last breadcrumb's `href` isn't specified.
   - Search when `list.search` is missing isn't covered.
   - Nothing covers what happens if `list.sort` is already the title field, which would duplicate "Title A–Z".
7. **`build.md` step 4, "Every screen … sets `data-state="loading"` at once":** the not-found screen has nothing to load. It's unclear whether it should flash `loading`.
8. **`build.md` step 4, "Computed custom fields":** "rounding to at least 1" means an empty post reads "1 min". That's probably fine, but it isn't stated.
9. **`build.md` step 1:** "every template" includes `screen-slide-over`, which a two-status type never uses. I inlined it anyway.
10. **`build.md` step 2:** the example's `publishRequires` comes from a free-text `conformance:` sentence. There's no rule for turning such sentences into config keys.
11. **`build.md` "What you produce" and `json-files.md`:** `path: ./content` doesn't say what it's relative to (I resolved it against the project root). The example config also drops the `./`.
12. **`behavior-spec.md` K5 and `templates/README.md`:**
    - No hand method is given for components whose ring is on a parent (tags) or that the browser draws (date segments).
    - Rule 4 doesn't list `readonly`, which the snippet sets on custom fields.
13. **`build.md` step 8:** it says to report axe as `needs the person` "when it cannot run". It doesn't say whether that counts against "done".

## 3. Guesses

- **Search:** falls back to the title field when `list.search` is missing.
- **Breadcrumbs:** the last crumb links to the current hash.
- **Not-found screen:** goes straight to `error`; it doesn't show `loading` first.
- **Publish order:** the publish checks run before the confirm dialog, so a blocked publish never asks first. The confirm button reads "Published".
- **Delete:** deleting a dirty item discards its edits without the discard dialog. A failed delete, even `unauthorized`, shows "Could not delete. Try again."
- **Status slide-over:** implemented for types with more than two statuses, though this schema never uses it.
- **Mount timing:** the save bar mounts only when the item is ready. The create dialog mounts with the collection screen and is removed when you leave it.
- **Labels and widths:** `reading_time` has the label "Reading time" and width `1/1`. The computed value is saved as a number.
- **Unattended defaults:** content is committed to git and uploads are not, with `uploads/` added to `.gitignore`.
- **Server binding:** `start.mjs` binds `127.0.0.1:4810` and serves `panel/` as root.
- **Seed data:** three posts covering both statuses plus a blank "Untitled" draft, and the settings record.
