# Conformance: Field Notes

Walked by hand in headless Chrome against `start.mjs` (real adapters, with a session cookie minted by `server/session.mjs`) and against `?test` (memory adapters). The repository's `npm run test:behavior`, `tools/lib/fidelity.js`, and axe were not run: this run counts as "elsewhere". The fidelity check below is a hand-written equivalent of the rule in `templates/README.md`.

| Check | Result | Evidence |
| --- | --- | --- |
| Every type has a collection view, an item view, and a create flow | pass | `#/post` lists 3 rows; `#/post/rail-line` opens the item; "New post" opens the create dialog, creates, and opens `#/post/<new id>` |
| Every singleton has an item view | pass | `#/settings` renders `screen-singleton` with Site title and Description |
| Every field appears in its item view with its declared type, width, and required rule | pass | Item view, in schema order: title text 1/1 required; slug slug 1/2; date date 1/2 required; cover image 1/2; tags tags 1/2; body markdown 1/1 required; reading_time custom 1/1. Settings: site_title text 1/1 required; description textarea 1/1 |
| Every `list.title`, `subtitle`, `sort`, and `search` entry names a real field | pass | title, date, -date, and title all exist on `post`; `node tools/validate.mjs` reports valid |
| Every adapter resolves to a recipe in `recipes/index.json` | pass | google-login, json-files, local-disk are all listed |
| Every behavior line is implemented: "Autosave drafts every 10 seconds" | pass | `panel.config.js` `autosave`. A dirty draft saved in the background after 10 s with fields enabled and "Saving…" shown; a published post did not autosave |
| Every behavior line is implemented: "Show word count under the body field" | pass | `panel.config.js` `wordCount: "body"`. Body help reads "13 words", then "2 words" and "450 words" as you type |

| Save state S1–S9 | pass | S1 clean on load; S2 dirty and back to clean; S3 saving disables fields, Delete, and remove-tag, but not the status button; S4 clean after save; S5 error keeps the edit with Save and Revert enabled; S6 Revert restores; S7 Cmd+S in clean makes no call; S8 `beforeunload` is prevented when dirty; S9 a nav link and the back button both open "Discard unsaved changes?"; Cancel keeps the screen and the URL, Discard goes |

| Create flow C1–C6 | pass | C1 asks for title and slug only; C2 the slug follows the title ("hello-world") until edited by hand; C3 runs V6; C4 created as draft with every field present, then the item opens; C5 a failure keeps the dialog and values and shows "Could not create. | google-login, server rules | pass | `/api/session` gives 401 without a cookie; an address not on the allow list gets 403; a write without `x-panel: 1` gets 403; logout clears the session (then 401); `allow.mjs` and `CONFORMANCE.md` return 404 from the static server; the allow list is not in `panel.config.js` |

| json-files hand checklist: `git diff` shows only the change; stopping the server mid-save leaves the old file | needs the person | Edit a post and run `git diff`; then stop `start.mjs` during a save and check that the save bar shows its error and the file is intact |
| google-login hand checklist (real credentials) | needs the person | Create a Web OAuth client with `http://localhost:4810` as an origin. Tick every box in `recipes/google-login.md` section 5: Google's button; an allowed address opens Home; a refused one shows "This account isn't allowed. | Deploying | needs the person | Runs on 127.0.0.1 only. To deploy, set `HOST`, add the site origin to the OAuth client, and serve over HTTPS (send `X-Forwarded-Proto: https` behind a TLS proxy) |
