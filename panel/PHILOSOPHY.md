# Philosophy

**Status: Open.** Not written yet. It will be derived from evidence gathered by walking a live Kirby panel. Do not treat anything below as a rule.

Until this file has principles, the design system is **Proposed**. Every visual choice made without a principle is logged in `DECISIONS.md` with the tag `philosophy-dependent`.

## Method

1. Open one screen of a live panel.
2. Write down the **feeling** it gives (calm, oriented, rushed, cluttered).
3. Find the **concrete property** causing that feeling (a measurement, a color, a placement, a behavior).
4. Record both in the table below.
5. When the same property appears on several screens, promote it to a principle.

Test for every principle: does it hold on a screen with one field and on a screen with fifty?

## Hypotheses (untested)

Verify each against the real panel. Confirm, revise, or discard.

1. **Low chrome, high calm.** Flat surfaces, almost no shadow, a neutral palette, color reserved for meaning (status, focus, primary action).
2. **Quiet labels, loud content.** Small muted field labels above inputs so the person's content is the heaviest thing on screen.
3. **A width grid for fields.** Half, third, and full widths so forms look composed.
4. **Constant orientation.** A breadcrumb header and the same layout on every view.
5. **Honest save state.** Unsaved changes always visible, with clear save and revert controls and Cmd+S.
6. **Drawers and dialogs keep context.** Edit related things without losing your place.
7. **Status as a first-class control.** Draft and published are one click away.
8. **Tight type scale, consistent density.** Few sizes, even spacing, one icon set.
9. **Speed.** Responses feel instant.

Candidate working principles (also unconfirmed): few primitives endlessly composed; content is the color; every screen has the same shape; scale by subtraction; speak human; state is always honest; no magic and no lock-in; say no on purpose.
