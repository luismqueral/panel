# Recipe: r2

Status: unverified. Written against `contracts.md`; the verification below has not been run. Say so to the person, and run it before calling the panel done.

## 1. When to use it

As `s3`, on Cloudflare R2. It fills the **files** contract.

## 2. Prerequisites

- An R2 bucket, and an R2 API token with "Object Read & Write" on that bucket only. Its access key and secret in `R2_ACCESS_KEY_ID` and `R2_SECRET_ACCESS_KEY`; the Cloudflare account id in the variable named by `account_env`.
- `url`: the bucket's public URL (an `r2.dev` subdomain or a custom domain).
- The project server.

## 3. Contract

Files, as in `contracts.md`, with the same key naming as `s3`.

## 4. Steps

Follow `s3.md` step by step, with these differences:

1. The endpoint is `https://<account id>.r2.cloudflarestorage.com/<bucket>/<key>`.
2. Sign with Signature Version 4, region `auto`, service `s3`.
3. Set `nosniff` and the SVG CSP with a Cloudflare Transform Rule on the public domain.

## 5. Verify

As `s3.md`, in the R2 dashboard.

## 6. Pitfalls

As `s3.md`. Also: the `r2.dev` URL is rate limited; use a custom domain for anything real.
